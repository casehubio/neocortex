## Part 3 — Adversarial Stress Test

### Ambiguous source text (metaphor, irony, unreliable narrator)

**Risk: Medium.** The methodology mentions metaphor in the NLP gap sweep context but doesn't address how the enrichment checklist handles metaphorical content. "I cut my hair" is literal, but "the broken column" is symbolic. The PAD/OCC assessment of a metaphorical statement should evaluate the INTENDED meaning, not the literal text. Should add a guidance note: "For metaphorical or symbolic content, evaluate the emotional intent, not the literal description."

**Unreliable narrator:** Biographical subjects narrate their own experience with bias. Frida's diary entries are subjective. The methodology assigns `STATED` confidence to direct quotes, but a subject's self-report can be unreliable. Should note: "Self-report content gets STATED origin but the confidence VALUE should reflect the reliability of the source (diary entry ≠ court transcript)."

### Contradictory information across passages

**Risk: Medium.** If passage 12 says "Frida forgave Diego" and passage 37 says "Frida never forgave Diego," the methodology has no reconciliation protocol. Both memories would be created with potentially contradictory PAD values and quality signals. Should add: "When contradictory claims exist, create both memories with provenance and add a `contradicts` attribute linking them. The confidence should reflect the source quality. Consolidation's BeliefRevisionPhase handles contradictions at runtime."

### NLP and LLM disagree on entity classification

**Risk: Low.** The methodology handles this well — NLP produces candidates, LLM reclassifies. The LLM's classification wins. The gap report catches entities NLP found but LLM excluded. No change needed.

### Central entity but cognitively shallow

**Risk: Low.** A person mentioned 20 times but only in passing ("Diego's assistant") gets Central tier by mention count but has no emotional depth. Phase 2b would spend effort on full cognitive enrichment for an entity with nothing to enrich. **Fix:** Depth tier should also consider EDGE count and MEMORY count, not just NLP mentions. A high-mention entity with few memories and few edges should be downgraded. The current criteria use "OR" (≥10 mentions OR ≥5 edges) — the mentions threshold alone can over-promote shallow entities.

### Sparse emotional content

**Risk: Medium.** Not all biographies are emotionally rich. A biography of a politician might be heavy on events and decisions but light on feelings. The OCC emotion checklist would produce low-intensity values everywhere, and SEC appraisal would be mostly neutral. This is correct behaviour — the checklist just produces low values. But the methodology should note: "Low or neutral values are valid — they indicate emotional neutrality, not a gap. The checklist ensures nothing is MISSED, not that everything is intense."

### Non-biographical source material

**Risk: High.** The methodology claims to be "source-agnostic" but is deeply biographical. Several steps assume a single subject ("the subject"), assume chronological narrative, assume personal relationships, assume emotional first-person perspective. For a technical document, research paper, or multi-person history, the methodology would break. **Fix:** Either remove the "source-agnostic" claim, or add adapter patterns for non-biographical material (multi-subject, third-person, non-emotional).

### Scale (1000 passages, 500 entities)

**Risk: Medium.** Phase 0 scales linearly (seconds). Phase 0.5 is O(passages) LLM calls — manageable. Phase 1 is O(passages) — manageable. Phase 2a is O(passages × artifacts) — this is the bottleneck. At 1000 passages with 3 artifacts each, that's 3000 enrichment calls. At ~2K tokens each, ~6M tokens total. Expensive but feasible. Phase 2b is O(central entities) — maybe 50-100 entities. The real bottleneck is Phase 2b context size for entities with many memories. Should note scaling guidance and suggest batching.

### Depth tier edge cases

**Risk: Medium.** The mention-count threshold (≥10 for Central) is arbitrary. In a short biography (30 passages), most entities will have <10 mentions, making very few Central. In a long biography (500 passages), even peripheral characters might hit 10 mentions. **Fix:** Mention thresholds should be percentile-based, not absolute. "Top 10% by mention count" adapts to corpus size automatically.

### Resolution dictionary circular dependencies

**Risk: Low.** The dictionary maps aliases → canonical names. It's a simple one-level mapping. Circularity would require "A → B" and "B → A," which the dictionary format prevents (canonical names are the target, never the source). No issue.

## Part 4 — Specific Gaps and Recommendations

### Gap 1: FormativeExperience event type not used

**What:** The methodology uses only `observation`, `action`, `outcome` for experience memories. The `FormativeExperience` type — designed specifically for biographical/developmental seeding — is never mentioned.

**Why it matters:** FormativeExperience carries `developmental-period` (childhood, adolescence, etc.), `situation-types` (CAPS input mapping), `salience-multiplier`, and `reinforcement-schedule`. These are critical for CAPS personality shaping. Without them, the extracted data can't drive personality development through the backstory seeder.

**Fix:** Add a decision rule in §3.1 Step 8: "If the experience occurred during a formative period (childhood, adolescence, early adulthood) and describes a character-shaping event (trauma, first love, parental relationship, identity formation), use `FormativeExperience` event type. Set `developmental-period`, `situation-types` (from the CAPS input node table in §4.6), and `salience-multiplier` (0.5-2.0 based on life impact)."

### Gap 2: Cognitive distortions not extracted

**What:** The model reference defines cognitive distortions (all_or_nothing, catastrophizing, overgeneralization, etc.) that warp CAPS settling. The methodology doesn't extract them.

**Why it matters:** Biographical text often reveals cognitive distortions explicitly. "Cut deeper than ANY physical pain" is a possible overgeneralization. "I NEVER painted dreams" could be all_or_nothing. These distortions shape personality and should be in the extracted data.

**Fix:** Add checklist item C3 under §4.6: "Identify any cognitive distortions present. Types: all_or_nothing, catastrophizing, overgeneralization, mental_filter, disqualifying_positive, mind_reading, fortune_telling, magnification, emotional_reasoning, should_statements, labelling, personalization." Store as `cognitive-distortions` attribute on the experience memory.

### Gap 3: Disposition profile not extracted

**What:** The model's personality system derives from 5 disposition axes (socialOrient, ruleFollowing, riskAppetite, autonomy, conflictMode). The methodology never extracts these.

**Why it matters:** Without the disposition profile, the CognitiveDerivationEngine can't derive PersonalityWeights, MoodBaseline, AppraisalWeights, CbrStrategy, or any of the 9 derivation pathways. The extracted data would have cognitive enrichment but no personality configuration.

**Fix:** Add a one-time Phase 2b step for the primary subject: "From all experience and relationship memories, infer the subject's position on each disposition axis. Use the cumulative evidence — patterns of behaviour, recurring choices, stated values. Each axis is a continuous value." This produces the CognitiveDefaults seed.

### Gap 4: No actual LLM prompt templates

**What:** The methodology defines what to extract and the output format, but never provides an actual LLM system prompt or user prompt template. Subagents need concrete prompts, not just checklists.

**Why it matters:** Different prompt phrasings produce dramatically different LLM output quality. Without a tested prompt template, each implementer will write their own, leading to inconsistent results.

**Fix:** Add an appendix with concrete prompt templates for: (a) Phase 0.5 gap sweep, (b) Phase 1 structural extraction, (c) Phase 2a passage-level enrichment, (d) Phase 2b entity-level enrichment. Each template should include the system prompt, the user prompt structure, and the expected JSON output format.

### Gap 5: No guidance on PAD aggregation across a passage

**What:** A passage may produce 3 experience memories. Each gets independent PAD values. But the PAD of the overall passage context affects all memories in it.

**Why it matters:** If memory 1 is joyful and memory 2 is angry, they're still in the same passage context. The methodology doesn't say whether to assess each memory's PAD independently or relative to the passage mood.

**Fix:** Add guidance in §4.1: "Assess each memory's PAD relative to its specific content, not the passage's overall mood. A passage can contain contradictory emotions (joy at recognition + anger at being labelled surrealist). Each memory captures its own affective state."

### Gap 6: Phase 2b context window overflow

**What:** Central entities can have 50+ memories. Fitting them all into a single LLM context window for Phase 2b enrichment is impractical.

**Why it matters:** Phase 2b requires "full entity context" but doesn't discuss what happens when that context exceeds the LLM window.

**Fix:** Add guidance in §5.2: "For entities with >30 memories, the Phase 2b subagent receives a summary of the full context: (a) all edges, (b) the 20 most significant memories (highest confidence, highest absolute PAD), (c) statistical summary of the remaining memories (count per domain, average PAD, dominant emotions). The subagent can request specific additional memories by ID if needed."

### Gap 7: Engagement domain explicitly excluded but not documented

**What:** The `engagement` memory domain tracks per-interaction social signals (responded, response-time-ms, reaction-count). The methodology never mentions it.

**Why it matters:** Engagement is a runtime signal from live conversations, not extractable from biography. But the absence should be documented so auditors don't flag it as a gap.

**Fix:** Add a note in §3.1 or §4: "The `engagement` and `affect` memory domains are runtime-only — they're populated by live conversation signals and MindMap node update events respectively, not by biographical extraction. Their absence from the extracted corpus is intentional."

### Gap 8: Depth tier thresholds are absolute, not relative

**What:** Central tier = ≥10 mentions. In a 30-passage biography with 40 entities, very few will reach 10. In a 500-passage biography, even minor characters might hit 10.

**Why it matters:** The tiers don't adapt to corpus size. A short biography produces too few Central entities; a long one produces too many.

**Fix:** Change to percentile-based: "Central = top 15% by combined mention+edge score. Supporting = next 35%. Peripheral = bottom 50%." This adapts automatically.

### Gap 9: No error handling or retry protocol for subagent failures

**What:** The orchestrator responsibilities describe the happy path. No mention of what happens when a subagent returns invalid JSON, times out, or produces out-of-range values.

**Why it matters:** At scale (hundreds of subagent calls), some will fail. Without a protocol, failures silently corrupt the output.

**Fix:** Add to §5.3: "Validate all subagent output: PAD values in [-1, 1], SEC values in [0, 1] (conduciveness in [-1, 1]), intensity values in [0, 1], emotion types from the 22 OCC enum, action tendencies from the 9 Frijda enum. Invalid output is quarantined and retried once. Persistent failures are logged in the coverage report as 'enrichment-failed' with the error reason."

### Gap 10: No contradiction handling

**What:** The methodology doesn't address what happens when two passages contain contradictory information about the same entity or relationship.

**Why it matters:** Biographies often contain contradictions — different accounts of the same event, evolving perspectives, unreliable narration.

**Fix:** Add guidance: "When passages contradict each other on factual claims, create both memories with provenance. Add a `contradicts` memory attribute linking them. Set confidence based on source quality. The consolidation pipeline's BeliefRevisionPhase handles contradiction resolution at runtime. For emotional contradictions (different feelings about the same entity at different times), these are natural and represent evolution — both are valid."
